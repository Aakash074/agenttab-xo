# AgentTab on XO

AgentTab's covenant migrated to an **XO template**, for the BCH BLAZE 2026 "Migrate To XO" bounty by General Protocols.

- **Original working project:** https://github.com/Aakash074/agenttab. It is a CashScript covenant, an x402-style paywall server, MCP tools for agents and a web app, and it is live on BCH mainnet.
- **This XO implementation:** https://github.com/Aakash074/agenttab-xo (this repository). The template is [`src/agenttab-template.ts`](src/agenttab-template.ts), with a JSON export in [`dist/agenttab.template.json`](dist/agenttab.template.json).
- **Chipnet proof:** [`docs/chipnet-proof.md`](docs/chipnet-proof.md). Every action (open, settle, cancel, refund) has been executed through XO invitations. The invitation files are in [`invitations/`](invitations).
- **What was hard in XO:** [`docs/xo-findings.md`](docs/xo-findings.md). It is a fact list with versions and repros.

## What AgentTab is

AgentTab is a refundable tab for an AI agent: one on-chain transaction to open, many paid API calls, one transaction to close.

1. The owner locks a budget in one covenant UTXO.
2. For each paid call, the agent signs an off-chain **voucher** for the cumulative amount owed. The voucher is a Schnorr data signature over `"AGENTTAB" ‖ tab outpoint ‖ amount (8 bytes)`.
3. The provider settles once with its best voucher. The covenant pays the provider at most the signed amount and forces the exact remainder back to the owner.

The provider can also cancel the tab. After a timeout the owner can refund everything. The agent's key can never withdraw.

## What changed in the migration

| | Original (agenttab) | XO version (this repo) |
|---|---|---|
| Covenant | `AgentTab.cash`, compiled by cashc 0.14.0 | **Unchanged.** The same compiled bytecode is embedded as CashASM (`src/agenttab-cashasm.ts`), following GP's `faucet_cash.ts` approach. `test/template.test.ts` proves it is byte-identical to cashc and gives the same P2SH32 address as the CashScript SDK. |
| Who builds transactions | The CashScript SDK `TransactionBuilder` in the server, MCP and web code | The XO engine, from a template and invitations that the owner and provider pass to each other |
| Opening a tab | The owner's wallet (WizardConnect / Paytaca) pays the contract address. The provider's pubkey comes from the server. | `openTab` start action with **both** roles:<br>- the owner sets `agentPublicKey`, `timeoutBlockHeight` and `budgetSatoshis`, and funds the tab;<br>- the provider joins and contributes `providerKey` (as a `providerKey.public_key` resolution).<br>Both keys are generated by XO. |
| Settle | The server calls `contract.functions.settle(...)` | `settle` follow-up on the tab's locking script, run by the provider:<br>- `voucher` and `amountSatoshis` are **provider-filled variables**;<br>- `<providerKey.schnorr_signature.all_outputs>` is the signature;<br>- the outputs are fixed by the template: provider `amount − fee` at index 0, owner `budget − amount` at index 1. |
| Cancel / refund | SDK calls | `cancel` (provider) and `refund` (owner) follow-ups. Refund sets `locktime: $(<timeoutBlockHeight>)` and a non-final input sequence. |
| Agent | An MCP tool signs vouchers | Unchanged: the agent is **not** an XO role. It signs vouchers off-chain (`scripts/tab.ts agent voucher`), and the provider puts the voucher into the settle invitation. |
| UX | Web app, paywall server, MCP | CLI scripts only. The bounty says the XO version does not need to copy the original UX. |

**Honest gaps.** The original's paywall server, MCP tools and web flow are not ported. This repo migrates the on-chain contract and its four transaction shapes to XO, and runs them two-party on chipnet. Workarounds for XO's current limits are marked `WORKAROUND` and `NOTE` in the code, and listed in `docs/xo-findings.md`. The two that change usage:
- owner and provider must run in separate processes;
- follow-ups re-pass `budgetSatoshis`, and refund re-passes `timeoutBlockHeight`.

## Reproduce on chipnet

Requires Node 25, which runs `.ts` directly.

```sh
npm install
npm test                                   # cashc byte-equality + CashScript address equality
node scripts/keygen.ts                     # fresh TEST mnemonics (owner, provider) + agent key -> .env (gitignored)
node --env-file=.env scripts/wallet.ts owner     # prints the owner's XO wallet address (bchtest:...)
node scripts/faucet.ts <owner bchtest: address> 100000   # chipnet.bch.ninja proof-of-work faucet
node --env-file=.env scripts/wallet.ts provider  # creates the provider wallet (needs no coins)

sh scripts/run-tab.sh t2 20000 1000 settle 7000  # open (owner+provider) -> agent voucher 7000 -> provider settle
sh scripts/run-tab.sh t3 10000 1000 cancel       # open -> provider cancel
sh scripts/run-tab.sh t5 10000 0    refund       # open with timeout = current lock height -> owner refund

node scripts/inspect.ts invitations/t2.open.json invitations/t2.settle.json   # validate + rebuild txids offline
node scripts/tx-status.ts <txid>                                              # confirmations and outputs on chipnet
```

`scripts/tab.ts` runs each step separately, one party per process: `open-create`, `open-accept`, `open-fund`, `sync`, `voucher`, `settle`, `cancel`, `refund`, `observe`, `release` and `status`. Invitations pass between the parties as files in `invitations/`.

To view an invitation in the XO debug tool (https://blaze.xo.cash):
1. Create a throwaway account.
2. Import `dist/agenttab.template.json`.
3. Import an invitation file, for example `invitations/t2.settle.json`.
